Manage your AI agent's skills through two types of tools: predefined tools that come built-in with the platform, and custom tools that you can create to extend your agent's functionality.

<Tabs>
  <Tab title="Tools (Predefined)">
    The **Tools (Predefined)** tab allows you to enable or disable built-in capabilities that your AI agent can use during conversations. Each tool represents a predefined function—such as answering FAQs, sending files, or escalating to a human agent—that can be toggled on or off depending on your business needs.  

    When a tool is enabled, additional configuration may be required before the agent can use it successfully. Some tools also depend on the **type of channel** where the end user is interacting (e.g., WhatsApp, Zendesk, Freshchat).  

    ---

    ## How to Enable or Disable a Tool

    1. Navigate to **AI Agent > Design > Skills** in the left menu.  
    2. Under **Tools (Predefined)**, locate the tool you want to manage.  
    3. Use the **toggle switch** to turn the tool on or off.  
    4. If the tool requires configuration, click **Configuration**, complete the required setup, and save your changes.  
    5. Check that the tool is supported by the **channels** your agent is connected to.  

    ---

    ## Available Predefined Tools

    ### **Send Files**  
    - **Description:** Allows the agent to send files directly to the user during a conversation.  
    - **Default:** Always enabled.  
    - **Configuration:** No setup required.  

    ---

    ### **Answer FAQs**  
    - **Description:** Enables the agent to respond to frequently asked questions about your product or service.  
    - **Default:** Always enabled.  
    - **Configuration:** No setup required. You can manage and update FAQs in the **Knowledge** section of the agent.  

    ---

    ### **Collect Information**  
    - **Description:** Enables the agent to collect, verify, and store user information (e.g., name, email, phone number) for lead generation or service requests.  
    - **Toggle:** Off by default.  
    - **Configuration:** Define the fields you want the agent to collect and where the data should be stored.  

    <Note>  
    This tool is **so important** that once enabled, it activates a dedicated **Collect Information tab** in the Skills section. From there, you can create, edit, and manage information collection configurations in detail.  
    </Note>  

    <Accordion title="How to Configure Collect Information">  
    1. Go to **AI Agent > Design > Skills > Collect Information**.  
    2. Click **New Configuration** to start.  
    3. Enter a **Name** for your configuration (e.g., `registro_interesados`).  
    4. Add any **Special Instructions** to guide the agent on how to collect the information.
    5. Add the fields you want to collect, specifying the name, type, and any validation rules.
    6. Assign the configuration to one or more **channels**.
    7. Click **Save** to activate.
    </Accordion>

    ---

    ### **Escalate to Human**  
    - **Description:** Enables the agent to transfer the conversation to a human agent when needed.  
    - **Toggle:** Off by default.  
    - **Configuration:** Requires a compatible integration (Freshchat or Zendesk) to be connected.  

  </Tab>

  <Tab title="Tools (Custom)">
    The **Tools (Custom)** tab lets you create your own tools—called **Skills**—that connect your AI agent to external APIs and services. This is the **Skill Builder**.

    A custom skill defines an HTTP request that the agent can trigger during a conversation. You configure the endpoint URL, HTTP method, input parameters, and the expected response format.

    ---

    ## Creating a Custom Skill

    1. Navigate to **AI Agent > Design > Skills**.  
    2. Switch to the **Tools (Custom)** tab.  
    3. Click **New Skill** to open the Skill Builder.  
    4. Fill in the skill details: name, description, URL, HTTP method, parameters, and return type.  
    5. Click **Save** to make the skill available to your agent.

    ---

    ## Skill Builder: Input Parameters

    Each input parameter you add to a custom skill requires:

    - **Name** — the parameter key.
    - **Kind** — the data type: `string`, `int`, `float`, `bool`, `list`, or `object`.
    - **Source** — where the value comes from: `conversation`, `end_user`, `state`, `store`, `config`, `fixed`, or `configuration` (for secrets like API keys).
    - **Location** — where the parameter is placed in the HTTP request.

    ### Parameter locations

    | Location | Label | Description |
    |---|---|---|
    | **query** | As a web-link extra | Added as a query string parameter in the URL |
    | **path** | Inside the web link | Fills a `{placeholder}` in the URL path |
    | **body** | In the message data | Sent in the JSON request body |
    | **header** | In the header | Sent as a custom HTTP header (common for API keys) |
    | **header_auth_bearer** | As a Bearer token | Sent as the `Authorization: Bearer <value>` header |

    <Tip>
      Use **As a Bearer token** when the external API expects an OAuth or JWT token in the standard `Authorization` header. This is especially useful when combined with the **end_user** source to forward tokens obtained through [External Login](/agent/en/external-login), since those tokens are stored encrypted and automatically decrypted before the request is sent.
    </Tip>

    ---

    ## Return Types

    Define what shape of data the external API returns so the agent can interpret it:

    | Return type | Description |
    |---|---|
    | **dict** | A bundle of details (JSON object) the agent can read fields from |
    | **list** | A list of items |
    | **number** | A single numeric value |
    | **str** | A plain text string |
