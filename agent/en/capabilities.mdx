Manage your AI agent's skills through two types of tools: predefined tools that come built-in with the platform, and custom tools that you can create to extend your agent's functionality.

<Tabs>
  <Tab title="Tools (Predefined)">
    The **Tools (Predefined)** tab allows you to enable or disable built-in capabilities that your AI agent can use during conversations. Each tool represents a predefined function—such as answering FAQs, sending files, or escalating to a human agent—that can be toggled on or off depending on your business needs.  

    When a tool is enabled, additional configuration may be required before the agent can use it successfully. Some tools also depend on the **type of channel** where the end user is interacting (e.g., WhatsApp, Zendesk, Freshchat).  

    ---

    ## How to Enable or Disable a Tool

    1. Navigate to **AI Agent > Design > Skills** in the left menu.  
    2. Under **Tools (Predefined)**, locate the tool you want to manage.  
    3. Use the **toggle switch** to turn the tool on or off.  
    4. If the tool requires configuration, click **Configuration**, complete the required setup, and save your changes.  
    5. Check that the tool is supported by the **channels** your agent is connected to.  

    ---

    ## Available Predefined Tools

    ### **Send Files**  
    - **Description:** Allows the agent to send files directly to the user during a conversation.  
    - **Default:** Always enabled.  
    - **Configuration:** No setup required.  

    ---

    ### **Answer FAQs**  
    - **Description:** Enables the agent to respond to frequently asked questions about your product or service.  
    - **Default:** Always enabled.  
    - **Configuration:** No setup required. You can manage and update FAQs in the **Knowledge** section of the agent.  

    ---

    ### **Collect Information**  
    - **Description:** Enables the agent to collect, verify, and store user information (e.g., name, email, phone number) for lead generation or service requests.  
    - **Toggle:** Off by default.  
    - **Configuration:** Define the fields you want the agent to collect and where the data should be stored.  

    <Note>  
    This tool is **so important** that once enabled, it activates a dedicated **Collect Information tab** in the Skills section. From there, you can create, edit, and manage information collection configurations in detail.  
    </Note>  

    <Accordion title="How to Configure Collect Information">  
    1. Go to **AI Agent > Design > Skills > Collect Information**.  
    2. Click **New Configuration** to start.  
    3. Enter a **Name** for your configuration (e.g., `registro_interesados`).  
    4. Add any **Special Instructions** to guide the agent on how to collect data.  
    5. Define your **fields** (see next section).  
    6. Assign the configuration to one or more **channels**.  
    7. Click **Save** when done.  
    </Accordion>  

    ---

    ### **Escalate to Human Agent**  
    - **Description:** Lets the agent transfer the conversation to a live human agent when it detects it can't resolve the request.  
    - **Toggle:** Off by default.  
    - **Configuration:** Requires a supported integration (Freshchat or Zendesk) to be connected.  

    ---

    ### **Send WhatsApp Flows**
    - **Description:** Enables the agent to send interactive WhatsApp Flows to users during conversations on the WhatsApp channel.  
    - **Toggle:** Off by default.  
    - **Availability:** Only available when a WhatsApp channel is connected through the Meta integration.  
    - **Configuration:** Link one or more WhatsApp Flows from your WABA (WhatsApp Business Account) and configure when and how the agent should send each one.  

    <Accordion title="How to Configure WhatsApp Flows">
    1. Go to **AI Agent > Design > Skills** and enable the **Send WhatsApp Flows** tool.  
    2. Click **Configuration** to open the Flows panel.  
    3. You will see a list of Flows available in your WABA. Linked flows appear at the top, separated from unlinked ones by a divider.  
    4. **Link a Flow** by toggling it on. Once linked, you can configure the following fields:
       - **When should the agent send this Flow?** — Describe the scenario (e.g., *When the user asks to book an appointment and has already shared their name*).
       - **Choose template where it is used** — Select the WhatsApp message template that contains this Flow.
       - **Language** — Choose the template language.
       - **After-send instructions** — Optional instructions delivered to the agent only after the Flow is sent. Leave empty to use the default.
       - **Agent instructions (Response handling)** — Control how the agent processes the user's response after they complete the Flow. See below for details.
    5. Click **Save** when done.
    </Accordion>

    #### Response handling mode

    When a user completes a WhatsApp Flow, their response is sent back to the agent. The **Agent instructions** setting lets you choose how much of that response the agent sees and how it should react. The raw response data is always saved in full regardless of this setting.

    | Mode | Description |
    |---|---|
    | **Send everything** *(default)* | The agent receives all of the user's responses and can reference them in the conversation. |
    | **Send only keys** | The agent receives only the field keys (not the values) and acknowledges receipt. Useful when you want confirmation without exposing sensitive data to the agent. |
    | **Acknowledgement only** | The agent does not receive any response content. Instead, it replies with a **customized message** that you define. |

    <Note>
    When you select **Acknowledgement only**, a required **Customized message** text field appears. Enter the message the agent should send to the user (e.g., *Thanks, we received your information.*). This field is mandatory.
    </Note>

    <Tip>
    Choose the response handling mode based on your privacy and UX needs. If the Flow collects sensitive information that the agent doesn't need to reference, **Send only keys** or **Acknowledgement only** are good choices.
    </Tip>

  <Tab title="Tools (Custom)">
    The **Tools (Custom)** tab lets you create your own tools — custom actions that extend your agent's capabilities beyond the built-in options. Custom tools are powered by **HTTP requests** to external APIs, allowing your agent to fetch data, trigger actions, or integrate with any system that exposes an API.

    ---

    ## How Custom Tools Work

    A custom tool is essentially an API call that the agent can trigger during a conversation when certain conditions are met. You define:
    - **When** the tool should be used (instructions to the agent)
    - **What** API endpoint to call (URL, method, headers, body)
    - **What parameters** the agent needs to collect from the user before making the call

    When a user's request matches the tool's trigger conditions, the agent collects the required parameters, makes the API call, and uses the response to continue the conversation.

    ---

    ## Creating a Custom Tool

    <Steps>
      <Step title="Go to Custom Tools">
        Navigate to **AI Agent > Design > Skills > Tools (Custom)**.
      </Step>
      <Step title="Create a new tool">
        Click **New Tool** to open the tool editor.
      </Step>
      <Step title="Configure the tool">
        Fill in the required fields (see configuration details below).
      </Step>
      <Step title="Test the tool">
        Use the **Test** button to verify the API call works correctly.
      </Step>
      <Step title="Save and enable">
        Click **Save** and make sure the tool toggle is turned on.
      </Step>
    </Steps>

    ---

    ## Tool Configuration

    ### General Settings

    | Field | Description |
    |---|---|
    | **Tool name** | A descriptive name for the tool (e.g., `Check Order Status`). |
    | **When to use** | Instructions that tell the agent when to trigger this tool (e.g., *When the user asks about their order status*). |
    | **After-use instructions** | Optional. Instructions for the agent after the tool runs (e.g., *Summarize the order details for the user*). |
    | **Channels** | Select which channels this tool is available on. |

    ### API Configuration

    | Field | Description |
    |---|---|
    | **HTTP Method** | GET, POST, PUT, PATCH, or DELETE. |
    | **URL** | The full endpoint URL (e.g., `https://api.example.com/orders/{order_id}`). |
    | **Headers** | Key-value pairs for request headers (e.g., `Authorization: Bearer {{token}}`). |
    | **Body** | Request body template (for POST/PUT/PATCH). Supports parameter placeholders. |

    ### Parameters

    Parameters are the data points the agent needs to collect from the user before it can make the API call.

    | Field | Description |
    |---|---|
    | **Parameter name** | The variable name used in the URL or body template (e.g., `order_id`). |
    | **Type** | Text, Number, or Boolean. |
    | **Description** | Tells the agent what this parameter is and how to ask for it. |
    | **Required** | Whether the agent must collect this before calling the API. |
