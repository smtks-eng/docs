Manage your AI agent's skills through three types of tools: predefined tools that come built-in with the platform, custom tools that you can create to extend your agent's functionality, and middlewares that run automatically before every reply.

<Tabs>
  <Tab title="Tools (Predefined)">
    The **Tools (Predefined)** tab allows you to enable or disable built-in capabilities that your AI agent can use during conversations. Each tool represents a predefined function—such as answering FAQs, sending files, or escalating to a human agent—that can be toggled on or off depending on your business needs.  

    When a tool is enabled, additional configuration may be required before the agent can use it successfully. Some tools also depend on the **type of channel** where the end user is interacting (e.g., WhatsApp, Zendesk, Freshchat).  

    ---

    ## How to Enable or Disable a Tool

    1. Navigate to **AI Agent > Design > Skills** in the left menu.  
    2. Under **Tools (Predefined)**, locate the tool you want to manage.  
    3. Use the **toggle switch** to turn the tool on or off.  
    4. If the tool requires configuration, click **Configuration**, complete the required setup, and save your changes.  
    5. Check that the tool is supported by the **channels** your agent is connected to.  

    ---

    ## Available Predefined Tools

    ### **Send Files**  
    - **Description:** Allows the agent to send files directly to the user during a conversation.  
    - **Default:** Always enabled.  
    - **Configuration:** No setup required.  

    ---

    ### **Answer FAQs**  
    - **Description:** Enables the agent to respond to frequently asked questions about your product or service.  
    - **Default:** Always enabled.  
    - **Configuration:** No setup required. You can manage and update FAQs in the **Knowledge** section of the agent.  

    ---

    ### **Collect Information**  
    - **Description:** Enables the agent to collect, verify, and store user information (e.g., name, email, phone number) for lead generation or service requests.  
    - **Toggle:** Off by default.  
    - **Configuration:** Define the fields you want the agent to collect and where the data should be stored.  

    <Note>  
    This tool is **so important** that once enabled, it activates a dedicated **Collect Information tab** in the Skills section. From there, you can create, edit, and manage information collection configurations in detail.  
    </Note>  

    <Accordion title="How to Configure Collect Information">  
    1. Go to **AI Agent > Design > Skills > Collect Information**.  
    2. Click **New Configuration** to start.  
    3. Enter a **Name** for your configuration (e.g., `registro_interesados`).  
    4. Add any **Special Instructions** to guide the agent's behavior during collection.  
    5. Add the **fields** you want the agent to collect. For each field, you can specify:
       - **Field name** — what you're collecting (e.g., `full_name`, `email`)
       - **Data type** — text, number, date, or boolean
       - **Required** — whether the field must be collected before the conversation can proceed
       - **Prompt instructions** — how the agent should ask for or extract this field
    6. Click **Save** when you're done.
    </Accordion>  

    ---

    ### **Human Escalation**  
    - **Description:** Allows the agent to transfer the conversation to a live human agent when it cannot resolve the user's query.  
    - **Toggle:** Off by default.  
    - **Requires:** A compatible integration (Freshchat or Zendesk) must be connected.  
    - **Configuration:** Set escalation rules and routing preferences.  

    <Note>  
    Human Escalation is only available when a supported integration is active. If no integration is connected, the tool will not appear or will be grayed out.  
    </Note>  

  </Tab>

  <Tab title="Middlewares">
    The **Middlewares** tab displays tools that run **automatically before your agent answers** every message. Unlike predefined or custom tools—which the agent decides when to invoke—middlewares always execute first, on every conversation turn.

    Middlewares call your systems to bring in context (such as the profile of the person writing) so that every reply starts with the right information. Your agent does not choose when to use them—they always run first.

    <Note>
    Middlewares are managed the same way as other tools (you can enable or disable them with a toggle), but they are separated into their own tab because of their unique behavior: they execute automatically on every message rather than being invoked by the agent on demand.
    </Note>

    ### Available Middlewares

    - **Get User Context** — Automatically retrieves contextual information about the user (such as their profile) from your connected systems before the agent formulates its reply.

    <Tip>
    Middlewares are especially useful when your agent needs up-to-date user data (like account status, subscription tier, or recent activity) to give accurate, personalized answers without asking the user for information your systems already have.
    </Tip>
  </Tab>

  <Tab title="Skills (Custom)">
    The **Skills (Custom)** tab lets you create your own tools to extend your agent's capabilities beyond the built-in options. Custom tools allow your agent to call external APIs, perform calculations, or execute any custom logic you define.

    Custom tools are invoked by the agent when it determines they are relevant to the user's request—just like predefined tools, but with logic you control.

    ---

    ## Creating a Custom Tool

    1. Navigate to **AI Agent > Design > Skills** and select the **Skills (Custom)** tab.
    2. Click **New Tool**.
    3. Configure the tool with:
       - **Title** — a human-readable name for the tool
       - **Description** — explain what the tool does (this helps the agent decide when to use it)
       - **Endpoint** — the URL the tool will call
       - **Method** — GET, POST, PUT, DELETE
       - **Headers** — any required authentication or custom headers
       - **Parameters** — define the inputs the agent should extract from the conversation
    4. Click **Save**.

    <Tip>
    Give your custom tools descriptive **Titles** — these appear in the **Task Log** and make it much easier to identify which tool was called during a conversation.
    </Tip>
  </Tab>
</Tabs>
